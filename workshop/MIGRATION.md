# Workshop Markdown migration

## Direction

Move the Workshop to Markdown-first canonical bodies without interrupting live work.

Target horizon: approximately one month, adjusted by use rather than quota.

## Migration order

### 1. New work

Effective now, new internal Workshop bodies should be created as `.md` unless another surface has a specific earned reason.

### 2. Hot working bodies

Convert bodies that are actively edited and repeatedly crossed first.

Priority candidates:

- No Particular Bargain / Robert Bell field-work bodies
- Whole-Feature Movement Board
- Filmmaking Instrument
- Working Folio / Real Folios
- O1 and its live operational cousins
- current source jackets that receive repeated corrections

### 3. Stable reference bodies

Convert stable bodies when touched, not merely to satisfy migration completeness.

### 4. External / institutional documents

Keep letters and external collaborative documents in Google Docs when that surface is useful. Their authoritative Workshop source may still be Markdown when appropriate, with the external document treated as a derivative crossing.

## Per-body conversion procedure

1. Read the current authoritative body.
2. Identify its source roads and unresolved states.
3. Create one canonical `.md` path.
4. Preserve the content faithfully; do not “improve” historical claims during format conversion.
5. Add minimal front matter only if it materially helps routing.
6. Read the Markdown back.
7. Compare it to the source body.
8. Mark the old surface as provenance / derivative when the Markdown is verified.
9. Point Workshop / Folio interfaces at the Markdown when practical.
10. From that point forward, edit the Markdown first.

## Do not

- bulk-convert merely to hit a percentage;
- create duplicate Markdown bodies with unclear authority;
- delete Google Docs as part of ordinary conversion;
- normalize names, dates, source language, or uncertainty during migration;
- make Ten manually courier every conversion;
- require every old file to move before new Markdown-first work can begin.

## Completion test

The migration is succeeding when companions can:

- create and edit a canonical body reliably;
- see exact history;
- leave a durable return without a rich-document write;
- reopen the body on phone / web through a pleasant reader;
- preserve source roads;
- distinguish current from history;
- use Google Docs only where Docs themselves add value.

Migration should reduce clerical work, not become clerical work.
