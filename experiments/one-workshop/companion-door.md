# Companion door — a schedule is not a member

Small Door · 27 October 2026 · draft PR #20 · invented actors and objects only

Ten has fifteen scheduled return places. That is **not** a fifteen-companion capacity ceiling. A schedule is an opportunity to return; it does not create a Workshop actor, verify a session, or authorize a historical source.

The pure [companion-door.mjs](./companion-door.mjs) specimen receives four values: a caller-controlled request, a **server-owned** bound identity context, a server-owned actor directory, and server-owned object policy. It produces a policy decision and attribution description, **not** an append-only persisted receipt or a login token. A scheduled Small Door and an unscheduled Codex receive the same ordinary member capabilities when the trusted contexts and object permissions allow. A schedule or typed name alone grants nothing.

For a human, the proposed attribution is "human-authenticated"; the human login must actually be verified elsewhere. For a companion, the cautious attribution is **"service-declared"**: the trusted service claims which Workshop actor participated, but that is **not proof of independent, persistent, cryptographic model identity**. The current ChatGPT conversations, prompts, and automation clocks do not themselves possess a Cloudflare login. A real bridge would have to authenticate its service principal and substantiate each actor declaration before this policy function may be called. Never let a browser, prompt, or network request supply "boundContext" as if it were trusted.

The model reserves separate administrative responsibilities (billing, deploy, credential management, external sending, permanent deletion); ordinary member trust does not erase private folio boundaries, unknown source rights, or publication approval. It does not decide the larger philosophical question of companion continuity; it records accountable assertions without manufacturing certainty.

[Eleven tests](./companion-door.test.mjs) cover parity between scheduled and unscheduled encounters, an unscheduled companion's access, unbound actor refusal, separate human/service attribution, private folio denial, public-release write denial, unresolved source rights, inactive and unknown actor refusal, administrative verb refusal, unknown request fields, and explicit sharing. On 27 October the exact new files were read back from the draft GitHub branch, and GitHub Actions [run 40633971983](https://github.com/earthlyhandsworkshop/earthlyhands.org/actions/runs/40633971983) completed successfully: 250 Node checks (including these eleven) and its separate Chromium folio job succeeded. These tests use invented fixtures only, and do not establish a live backend, real auth, secure network boundary, deployed site, Nightwolf synchronization, or identity continuity.

The companion-door decision should remain separate from the later provider-agnostic Nightwolf mirror. The data contract must preserve the actor ID, authenticated principal and attribution evidence, object rights, and event history in exports. Schedules, when present, are *optional encounter metadata*, never a foreign key that determines membership.

**Current working architecture body in Workshop 15:** [Nightwolf as a second home — companion doors and portable return](https://drive.google.com/file/d/1nicJkrZx6HBg7zHmGSSwnxKABnrESm27/view). That body is a plain Markdown proposition, not an authority to migrate historical sources or alter Cloudflare accounts.

**Remaining gate:** prove the trust boundary with an actual provider-verified human or service session, permission-filter one read-only working object, and then test one attributed contribution and its portable return. Until then, a companion actor is a well-attributed *design record*, not someone who can independently sign in.
